# 아카이브인가? — 수집·비평 경계 기준 (초안)

meta-archives.xyz가 Are.na [meta-archive](https://www.are.na/daehwan-jang/meta-archive) 채널에서 **무엇을 비평 대상으로 볼 것인가**에 대한 운영 기준 초안이다. 보편적 아카이브 정의가 아니라, 이 프로젝트의 **관찰·비평 실천**을 위한 경계선이다.

관련 문서: [concept.md](../concept.md), [meta-archive-inventory-review-2026-06-22.md](meta-archive-inventory-review-2026-06-22.md), [schema.md](../schema.md)

*작성: 2026-06-22 · 초안 — 판정은 재논의 가능*

---

## 1. 두 단계를 구분한다

| 단계 | 행위 | 태도 |
|------|------|------|
| **수집** (Are.na) | *딸깍* — 그럴듯한 것, 비평하면 재미있을 것 | **관대** |
| **비평** (meta-archives.xyz) | 구조·형식·분류를 읽고 글·YAML로 남김 | **선명** |

「분류라는 예정된 실패」가 말하듯, 수집은 분류보다 먼저 온다. 경계가 흐릿한 항목이 채널에 있는 것은 **오류가 아니라 수집의 자연스러운 결과**다. 다만 비평 일정·YAML 작성·글 발행으로 넘어갈 때는 기준이 필요하다.

---

## 2. meta-archives가 읽으려는 것

이 프로젝트의 아카이브는 *저장소*라기보다 **기억의 구성 방식**이다. 비평은 다음이 드러나는 **구조**를 읽는다.

- 무엇을 수집하고 무엇을 배제하는가 (F: 수집 단위)
- 분류·메타데이터가 어떤 세계를 만드는가 (C: 분류 = 관계 모델)
- 기술·UI가 어떤 탐색·접근을 강제하는가 (D, E)
- 형식이 내용과 결합하는가 (B: 형식 = 내용)
- 시간·출처·맥락이 어떻게 층위화되는가 (H, I)

**DB·마켓·영감 보드**도 아카이브처럼 *보일* 수 있다. 판별 질문은 "아카이브라고 부르는가"가 아니라 **「아카이브의 구조를 비평할 밀도가 있는가」**에 가깝다.

## 3. 판정 등급

| 등급 | 코드 | 의미 | meta-archives 처리 |
|------|------|------|-------------------|
| **핵심** | `A` | 아카이브 자기인식·구조가 분명. 비평의 정석 대상 | `data/archives/` YAML + 비평글 |
| **주변** | `B` | 아카이브적이거나, 아카이브 경계를 비평하기 좋음 | YAML 권장. 비평·에세이 가능 |
| **레퍼런스** | `C` | 큐레이션·DB·영감. 구조는 있으나 *기억의 구성*보다 *참조*에 가까움 | Are.na 유지. 비평 우선순위 낮음 |
| **메타** | `D` | 아카이브 *에 관한* 사이트(심포지엄, 목록, 이벤트) | 주제글·에세이로는 가능, 개별 아카이브 비평은 아님 |
| **제외 검토** | `E` | 이 프로젝트 질문과 어긋남. 채널 정리 후보 | 별도 채널 이전 또는 삭제 검토 |

등급은 **고정 라벨이 아니다.** 관찰이 깊어지면 바뀔 수 있다(B→A, C→B 등).

## 4. 판별 신호 (체크리스트)

각 항목에 대해 ○ / △ / × 로 표시한 뒤, 종합 판정한다. **만장일치가 아니어도 된다.**

### 아카이브에 가까운 신호

| # | 신호 | 질문 |
|---|------|------|
| S1 | **자기명명** | 스스로 archive / 아카이브 / collection / repository라고 말하는가 |
| S2 | **누적** | 시간에 따라 쌓이는 기록 집합인가 (일회성 이벤트·피드만이 아닌가) |
| S3 | **엔티티** | 반복 가능한 수집 단위(item, text, place…)가 있는가 |
| S4 | **분류·메타** | taxonomy·메타데이터가 세계관을 드러내는가 |
| S5 | **배제의 흔적** | 무엇을 넣지 않았는지 읽을 수 있는가 |
| S6 | **맥락·출처** | 기록의 출처·시간·관계를 남기려 하는가 |
| S7 | **형식 실험** | 구조·인프라가 메시지와 맞물리는가 (비평 hook) |

### 아카이브에서 멀어지는 신호

| # | 신호 | 질문 |
|---|------|------|
| W1 | **1차 목적** | 판매·광고·구독·이벤트 등록이 중심인가 |
| W2 | **영감·레퍼런스** | "inspiration", "best of", "showcase"가 본질인가 |
| W3 | **거래** | 마켓플레이스·가격이 구조의 핵심인가 |
| W4 | **발행** | 출판사·미디어의 상품 목록에 가까운가 |
| W5 | **휘발** | SNS 피드·트렌드 추적이 본질인가 |
| W6 | **집계만** | 큐레이션 없이 크롤·링크만 모았는가 |

**경험적 규칙 (초안):**

- S1~S3 중 **2개 이상 ○**이고 W1~W3이 **×** → `A` 또는 `B` 후보
- W2 또는 W3이 **○**이면 → 기본 `C` (예외: 구조가 극도로 독특하면 `B`)
- S1 **×**이고 W2 **○** → `C`
- 이벤트·심포지엄·목록의 목록 → `D`

## 6. YAML 확장 (boundary 블록)

`data/archives/_template.yml`에 추가할 파일럿 필드:

```yaml
boundary:
  grade: null          # A | B | C | D | E
  reviewed_at: null    # YYYY-MM-DD
  note: null           # 판정 근거 한 줄
```

비평 우선순위: **A → B (경계 중) → B (일반) → C**. D는 에세이·주제글로만.

## 7. 권장 운영

### Are.na 채널

- **유지:** `C`·`D`도 수집 단계에서는 남긴다. 경계 사례는 오히려 분류 논의의 재료다.
- **정리 검토:** `E`로 판정된 항목만 별도 채널(예: `web-inspiration`)로 이동.

### `meta-archives.md`

- 테이블에 `등급` 열 추가는 *선택*. 당분간 이 문서의 판정표를 참조.
- `디자인 영감·레퍼런스 (경계)` 그룹명 유지 — "비평 제외"가 아니라 "등급 C 집합"임을 명시.

### `data/archives/`

- 우선 **A·B**만 YAML 작성.
- `C`는 판정만 이 문서에 남기고, 구조가 궁금해지면 그때 YAML (예: `discogs.yml`).

### 비평글 주제로 쓸 수 있는 *경계* 각도

| 각도 | 예시 |
|------|------|
| 아카이브 vs DB | Discogs, Fonts In Use |
| 아카이브 vs 영감 보드 | Godly vs Letterform Archive |
| 아카이브 vs 출판 | Stripe Press vs Adocs |
| 아카이브 vs 이벤트 | 건축의 아카이브 해제 vs MACBA Archive |
| 메타 아카이브 | LACA Alternative Libraries |
| 극소 엔티티 | Chocolate Milk vs PublicStairs |

## 8. 한 문단 선언 (초안)

> meta-archives.xyz는 **기억을 어떻게 구성하는가**를 형식으로 읽는다. Are.na 채널은 그 후보를 넓게 모으고, 비평은 그중 **구조의 밀도가 높은 것**에 집중한다. 웹 디자인 영감 보드나 마켓플레이스는 채널에 남을 수 있으나, 우선 비평 대상은 아니다. 다만 *아카이브와 무엇이 다른가*를 묻는 글에서는 이들이 비교 대상이 될 수 있다.
